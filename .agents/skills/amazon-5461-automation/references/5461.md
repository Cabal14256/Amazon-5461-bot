# 5461 Submission Reference

> 位置: `projects/amazon-5461-bot/`
> 最后更新: 2026-04-28

## 流程概述

完整的 5461 申请流程:

```
Add Product 页面
    ↓
填写表单 (Item Name, Brand Name, No Product ID)
    ↓
点击 Next
    ↓
检测页面结果（三种可能）
    ├─→ 进入 /description → 已有权限，无需 5461
    ├─→ Brand Authorization Required → 继续 5461 流程
    └─→ 停留在 Product Identity → 检查表单验证/品牌问题
    ↓
点击 Apply to sell
    ↓
5461 表单加载 (Listing approval)
    ↓
（可选）品牌选择页 — 点击历史申请行触发新表单
    ↓
填写 5461 表单字段:
    - Product title
    - Manufacturer
    - Product Description
    - Contact email
    - Contact phone (可选)
    ↓
勾选文档上传确认项（5个复选框，限定在 QualificationWidget 内）
    ↓
上传产品图片
    ↓
点击 Submit
    ↓
等待 Case ID
```

## 详细执行顺序

### Phase 1: Add Product 表单

1. Fill **Item Name** (from brand copy)
2. Select **Item Type Keyword** (e.g., Electronics > Accessories & Supplies > Cell Phone)
3. Ensure `"This product does not have a brand name"` is **UNCHECKED**
4. Fill **Brand Name** in UPPERCASE (e.g., `HOMEMO` not `homemo`)
5. Check `"This product does not have a Product ID"`
6. Click **Next**

**Important**: Even if the Next button appears disabled, attempt to click it via the inner shadowRoot button.

### Phase 2: Detect Page Result

After clicking Next, wait 5 seconds then check:

```python
if "/description" in current_url:
    return "已有权限，进入产品详情页"  # PASS - no 5461 needed

if "Brand Authorization Required" in page_text:
    # Continue to Phase 3

if page_state == "PRODUCT_IDENTITY":
    # Form validation failed or other issue
    # Check: Brand Name state, variations checkbox, etc.
```

### Phase 3: Apply to Sell

1. Click **Apply to sell** button
2. Handle popup visibility issue: force-show via JS if `display='none'`
3. Check for "Clarify which brand" page → use [brand-keywords.md](brand-keywords.md)
4. If historical applications exist, click the **clickable kat-box** row to trigger new form:
   ```python
   page.locator('kat-box[class*="clickable"]').first.click()
   ```

### Phase 4: Fill 5461 Form

1. Fill **Product title** (extracted from brand copy)
2. Fill **Manufacturer** (brand name)
3. Fill **Product Description** (full brand copy text)
4. Fill **Email** (from account config)
5. Upload **images** (from `brand_packs/{brand}/images/`)

### Phase 5: Checkboxes

Only check the **5 checkboxes inside the QualificationWidget**:
- NEVER check "This product does not have a brand name"
- Scope queries to the QualificationWidget container only

### Phase 6: Submit

1. Click **Submit**
2. Wait for confirmation
3. Extract **Case ID** (handles multiple formats, see [edge-cases.md](edge-cases.md))
4. Log Case ID to database immediately

## 执行脚本

### 单账户执行

```bash
python scripts/run_full_5461_workflow.py us_store_530 OUNNE
```

选项:
- `--dry-run`: 模拟执行
- `--site US|UK|DE|MX`: 选择站点文案

### 批量执行

```bash
# 使用配置文件示例
python scripts/run_full_5461_batch.py --config config/batch_config.example.json

# 直接指定
python scripts/run_full_5461_batch.py \
    --accounts us_store_530,us_store_529 \
    --brands OUNNE,WILLONE \
    --batch-size 2

# 跑全部品牌
python scripts/run_full_5461_batch.py --accounts us_store_550 --brands all --site US

# 中断后恢复
python scripts/run_full_5461_batch.py --config config/batch_config.example.json --continue-from 2
```

### 新版统一入口

```bash
python submit_5461.py us_store_530 OUNNE
```

## 注意事项

1. **AdsPower 浏览器**必须在运行前启动
2. **人工确认**默认开启，提交前会暂停等待确认（use `--yes --no-confirm` to skip）
3. **表单验证**是实时的，填写后错误状态自动清除
4. **提交按钮**在表单完整且有效前保持禁用
5. **文件上传**支持多选，格式限制 png/jpeg/jpg，最大 10MB
6. **品牌名必须大写**，否则表单验证失败
7. **Next 按钮即使 disabled 也要尝试点击**（通过 shadowRoot 内层 button）
8. 点击 Apply to sell 后，**背景 Product Identity 页面保持原样** — 这是正常设计

## 故障排除

See [troubleshooting.md](troubleshooting.md) for detailed diagnostics.

Quick fixes:
- **页面加载超时** → 检查 AdsPower 浏览器 / 网络 / 增加超时
- **表单填写失败** → 检查选择器 / 查看截图 / 检查品牌资料包
- **文件上传失败** → 检查文件路径 / 格式 / 大小
- **Error 410001 / 429** → 视为限流/风控状态：截图和 console 留证，关闭右侧表单，随机拟人化等待后受控重试 Apply to sell / Select a brand；若无 Case ID、字段缺失或状态不明确，先查 Dashboard 再决定是否续接 Draft 或重试。
- **品牌硬封锁** → 换账号或放弃该品牌
